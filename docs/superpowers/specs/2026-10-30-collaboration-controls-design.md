## 消息唤醒与重试

`pending / seen / replied / read` 继续表达消息阅读和回复状态。另行记录每条消息的唤醒尝试、时间、原因和次数：待投递、已尝试唤醒、唤醒失败。成功启动唤醒不证明对端已经收到或阅读消息。

重试复用现有消息及其当前收件人，不创建第二条消息。仅待处理消息可重试，已读或已回复时拒绝；调用者必须为参与会话或现有人工控制台身份。并发重试须互斥，并保留现有唤醒开关、忙碌判断、去重和并发上限。不启动无限后台重试。

HTTP、MCP、CLI 与网页使用同一 core 逻辑；错误和状态可读，审计不记录密钥或消息正文。旧消息及导入数据缺少唤醒记录时不凭空标记失败。

## 受管运行实例

RuntimeAgent 是可复用启动预设；RuntimeInstance 是一次实际运行，独立保存生命周期。Conflux 创建实例 ID 并传入启动环境，由真实运行时连接绑定会话及 PID。终端启动器 PID 不能冒充运行时 PID。

停止前必须同时核实实例记录、会话绑定、PID、进程类型和进程创建身份；无法证实或 PID 已复用时拒绝终止。未受管会话不提供任意 PID 终止入口。尚未绑定真实 PID 的启动不能声称已安全停止。

恢复创建新实例，保留原运行时、工作目录、会话恢复目标及预设配置；避免重复运行和调度重叠。密钥仍只由现有预设配置提供，不复制进实例列表或审计。进程检查和终止器可注入，自动回归不得启动或结束用户的真实会话。

## 会话候选确认

完整 Conflux 会话 ID 是定位依据。名称和 Ghostty 等终端标题可能变化，无法精确匹配时查询当前可见目录，结合名称片段、项目路径、运行时及活跃时间返回最多三个候选，并标明匹配原因。仅完整 ID 精确相等免于消歧；所有模糊匹配都要求用户选择。

通过 Conflux 技能引导助手主动调用宿主选项问答，缺少此能力时用编号列表；允许用户否定候选、补充线索。查询不发送、不唤醒，用户确认后重新核实 ID。MCP 不承诺控制宿主原生弹窗或扫描未登记会话。

## 颜色和主题

界面作为长时间使用的开发协作工作台：保留汇流蓝作为主要动作色，用纸面、面板、分隔线建立层次。沿用 IBM Plex 字体、现有导航与信息密度，不增加装饰性页面重排。

浅色和深色分别提供 success、warning、danger、info、neutral 语义色及柔和底色。在线为成功，忙碌为警告，失败为危险，已结束/过期为中性；所有状态同时保留文字或图标。主按钮前景依据色板推导，不能在浅亮强调色上固定白字。

保留预设名称、本地存储键和自定义色板的八个字段。语义色由当前明暗模式补充，不强迫旧主题增加字段。具体令牌及对比度约束见 [DESIGN-TOKENS](../../DESIGN-TOKENS.md)。
