# 侧边栏会话 × 消息流合并（工作台视图）设计

> Issue #14「侧边栏会话跟消息流考虑合并」
> 日期：2026-09-16 · 分支：feature/sidebar-merge-message-feed

## 问题

当前「会话」与「消息流」是两个平级 tab：

- 「会话」= 按项目分组的会话卡片列表（状态/忙碌/待回复徽标/搜索），点选后仅在右侧 DetailPanel 展示静态详情；
- 「消息流」= 全局消息卡片流 + @composer，与单个会话的对话被压缩在顶部一个 `max-h-48` 的折叠框里。

两视图信息重复（会话 ↔ 消息本是一体两面），交互割裂：想跟某个会话说话要先切 tab、@ 搜索目标，而线程视图又小又不可扩展。

## 方案：双栏工作台

侧边栏两项合并为一个 tab「会话与消息」（`workbench`），主区为双栏：

```
┌──────────┬─────────────────────────────┐
│ 会话列表  │  上下文消息区                  │
│ (w-80)   │  未选会话 → @composer + 全局   │
│ 搜索      │            消息流（原消息流）   │
│ 项目分组  │  已选会话 → 与该会话的对话线程   │
│ 状态徽标  │            + 固定目标输入框     │
└──────────┴─────────────────────────────┘
```

### 左栏（会话列表）

继承原 SessionsTab 全部能力：搜索（名称/正在做什么/项目路径）、按项目分组 + 组内组间按最近心跳排序、StatusDot、`N 待回复` 徽标。点选会话 = 主导航：右栏切换为该会话的对话线程（同时保留 App 级选中，DetailPanel 照旧同步）。

### 右栏（上下文消息区）

- **未选会话（落地态）**：保留原 MessageTab 全部能力——@composer、状态过滤、内容搜索、全局消息卡片流。点卡片 = 选中消息（DetailPanel）+ 打开与对方的线程。能力无损失，只是成为次级视图。
- **已选会话（线程态）**：与该会话的往来消息以聊天气泡全高展示（`usePeerMessages`，mine = `web-console`），底部固定目标输入框（`webAsk` 直接发往该会话，无需再 @）。头部含对方状态徽标与「收起」。

### 联动

- 图拓扑 tab 点选会话 → `selectedSessionId` 变化 → 工作台右栏自动打开对应线程（下次进入时）。
- 「收起」只清空本地 peer，不改 App 级选中，DetailPanel 不受影响。

## 非目标

- 不动数据层/HTTP 接口（`getSessions`/`getMessages`/`getPeerMessages`/`webAsk` 原样复用）。
- 不动 DetailPanel、图拓扑、@mention 选择逻辑（MentionComposer 原样保留在落地态）。
- 不引入新依赖。

## 取舍记录

- 线程态输入框不复用 MentionComposer（其目标态为内部管理、面向自由 @ 挑选），改为轻量固定目标输入——语义即「对话窗口里输入即发」。
- 保留全局消息流为落地态而非删除：跨会话总览/搜索是独立价值，且使合并零能力损失。
