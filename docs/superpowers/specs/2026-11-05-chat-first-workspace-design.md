## 1. 产品目标与范围

用户打开 Conflux 后直接找到当前协作、输入任务并查看结果；图谱帮助理解协作关系；助手页负责配置和启动。主导航统一为「聊天」「助手」「活动记录」「设置」。

本批交付 P1—P4：

1. 聊天成为默认工作界面，房间与最近会话可以直接进入；恢复上次有效房间。
2. 当前房间的聊天与图谱相邻切换，全局图谱仍可访问。
3. 原 Agents 与运行时入口整合为助手页，明确模型助手、编码助手、运行实例与会话。
4. 完成状态、异常、可访问性、浏览器和实际桌面入口验收。

后续 P5 为独立设计项目：模型助手参加多方聊天室。P1—P4 不承诺此能力，不需要以 P5 为发布前置。

本批保持后端 Agent / RuntimeAgent 类型、数据库表、房间成员归属、HTTP/MCP/CLI 协议和进程身份校验不变。不会自动建房、自动启动助手、自动唤醒或自动发送消息。不引入自动编排、跨房间成员关系、全新主题系统或图布局算法。

## 2. 当前实现与问题

| 当前代码 | 已存在的能力 | 本批调整 |
| --- | --- | --- |
| `apps/web/src/App.tsx` | 默认 `graph`，多个视图保活 | 默认聊天，明确工作界面选择状态，低频视图按需加载 |
| `components/Sidebar.tsx` | 图谱、消息流、Agents、聊天室；底部运行时、设置 | 主入口收敛，房间和最近会话成为导航主体 |
| `components/RoomsTab.tsx`、`RoomChat.tsx` | 房间卡片、任务、广播、定向召唤 | 房间列表与当前房间分离，聊天直接占据主区 |
| `components/MessageTab.tsx` | 全局消息与基于 peer 的单聊 | 提取可受控单聊组件，全局消息成为活动记录 |
| `components/AgentTab.tsx`、`ChatPanel.tsx` | 模型 API 助手与独立对话 | 并入助手页的模型助手分类，独立对话继续可用 |
| `components/RuntimesTab.tsx`、`RuntimeInstancesPanel.tsx` | CLI 预设、PTY、受管实例停止/恢复 | 并入编码助手分类，配置与实际运行状态分开表达 |

已经确认的实现边界：

- `sessions.chat_room_id` 是成员归属事实来源；一个会话同时只属于一个房间。不要从旧 `topology` JSON 重建归属。
- `GraphNode.chat_room_id`、`ChatRoom.members` 足够构造房间图谱范围，无需新增数据库字段。
- 单聊复用 `GET /web/peer-messages?peer=…` 与 `POST /web/ask`。不得通过 `roomId=0` 或虚构房间走召唤接口。
- 编码助手预设关联会话依赖 `GraphNode.agent_id`；受管实例通过 `preset_id` 与 `session_id` 关联。相同名称不构成关联证据。
- `useMessages` 当前查询包含 `checkInbox` 副作用；把页面隐藏并不等于停止查询。重排布局时必须明确查询启用条件。
- 当前房间聊天使用轮询，图谱使用 React Flow。保留这些机制，不用此次整理引入全新的推送协议。

这是布局规格，不是已经完成的视觉稿。实现沿用 `docs/DESIGN-TOKENS.md` 的主题、字体、状态色和阴影。字号取仓库规则与令牌文档中更严格的下限（当前令牌文档为 11px）；主列表和正文不低于 12px。不要增加裸灰阶或按助手类型给整个页面染色。

## 4. 导航、首次进入与恢复

### 4.1 默认行为

- 每次启动进入聊天主入口，默认子视图为聊天。上次停在图谱、助手或设置不改变启动默认。
- 房间列表成功后，先恢复上次房间的 `id + created_at`；匹配失败则选择列表中 `updated_at` 最新的房间，时间相同按 id 降序稳定排序。
- 没有房间时展示引导：主要按钮「创建聊天室」，次要入口「接入已有会话」和「配置编码助手」。仅打开相关说明或配置界面，不自动执行接入命令。
- 创建成功直接选择新房间。允许创建空房间，空房间显示「添加成员」；没有成员时禁止广播和定向发送。
- 删除当前房间后重新选有效房间，没有剩余房间则回到引导；请求失败或断网不能被解释成房间已删除。

### 4.2 前端状态与持久化

使用前端判别联合区分目标：`room`、`session`、无目标。模型助手的独立对话保留在助手页面，避免把模型助手 id 混入 session id。

新增键 `conflux.workspace.v1`，仅保存版本号、上次房间的 id 与 created_at、详情展开偏好。读取必须捕获 JSON 错误、不可用存储、错误版本和类型；写失败不影响当次交互。

恢复必须等待房间列表成功后核对。`id + created_at` 是 UI 恢复提示，不是数据库身份或授权依据；此偏好永不用于发送、进程控制或数据访问授权。不保存 API 密钥、提示词正文、消息正文和终端输出。

每个房间、单聊的未发送草稿在内存中以目标类型与完整 id 为键保存；切换视图和助手页面不清空。重启应用不恢复正文草稿。发送成功只清除提交时版本的草稿：发送中继续输入的新文字必须保留。

## 5. 聊天、成员与任务

### 5.1 房间聊天

- 直接使用真实房间 id 加载线程与任务；任务和广播消息保留来源标签，禁止以不同资源的相同数字 id 互相覆盖。
- 任务的 prompt/result 是一条任务的请求和结果，不为每次轮询重新追加。原始消息与任务展示保持其各自语义，不伪造一套已去重的后端事件流。
- 选择 `@成员` 后，以完整会话 id 定向；重名候选同时显示项目、运行时与 id 短标识。文字名称不作为路由依据。
- 未选目标时输入区明确显示「发送给当前房间全部成员」。候选只来自当前房间，不把其他房间或模型助手混入候选。
- 成员离房、目标失效或房间删除时保留草稿，阻止向旧目标发送，展示原因。离线会话沿用现有唤醒规则，文案区分排队、唤醒尝试、已读与已回复。
- 一次点击提交一次请求，提交期间禁用重复提交；输入法组合输入期间 Enter 不发送。网络结果不确定时保留草稿并提示核对记录，不自动重发同一提问。
- 默认发送身份沿用 `web-console`；导航与图谱切换不修改发送身份、不代表其他会话发送。

### 5.2 单聊

点击最近会话进入以其完整 session id 为目标的单聊，复用 peer 消息与 webAsk 路径；不改变房间成员归属。当前目标不属于任何房间也可单聊。

会话名称改变时目标保持原 id。会话已结束时仍可查看历史；发送资格与唤醒限制沿用现有服务端结果，不在 UI 假定所有结束会话都可恢复。

单聊顶部不显示「当前房间图谱」；提供「在全局图谱中查看」。存在所属房间时额外提供「进入所属聊天室」。

### 5.3 详情面板

房间详情包含成员、任务概览、添加/移出成员与房间删除入口；原成员管理能力不能因房间卡片移除而丢失。成员只能从尚未入房的有效会话中添加，本批不支持静默把会话从另一房间搬来。

删除房间需要明确的二次确认，说明沿用现有删除语义。P1 不修改后端删除策略，也不宣称删除房间会删除全部会话。单聊详情显示会话身份、项目、状态和原有终端/详情操作。

## 6. 图谱的位置与范围

- 房间顶部的「聊天 / 图谱」是同一房间的两个视图；切换不改变目标、成员、草稿或任务。
- 房间图谱包含 `ChatRoom.members` 对应的现有节点与两端都在成员集合内的现有边；孤立成员也显示。房间外节点、跨房间边与 `web-console` 不自动混入成员图。
- 找不到节点的成员显示在详情的「暂无法加载的成员」提示中，不伪造 active 节点。所有边沿用真实 channel id 与方向。
- 初次进入房间图谱默认展示全部成员，不套用全局「仅活跃」过滤造成空图。该模式不展示会扩大范围的「全部」全局过滤器。
- 「查看全局图谱」明确切换为全局范围，展示范围标识和「返回当前对话」。从全局选中节点仅打开详情，发送必须由显式「与此会话对话」动作进入聊天目标。
- 各房间、全局图谱的缩放与拖拽位置分别以范围 key 在内存保留；只保留一个图谱渲染器，不为每个访问过的房间常驻一棵 React Flow 组件树。切换范围后清空不属于该范围的节点/边选择。现有手工边曲率存储键继续读取，不删改旧主题和图谱偏好。
- 首次进入聊天不加载 React Flow 布局/渲染模块；图谱首次打开才挂载。隐藏后保留交互状态但暂停布局重算、窗口事件与图谱专属定时器；再次打开以最新数据更新一次。
- 工作界面只保留一个公共 graph 数据查询用于会话身份与状态，默认五秒刷新；房间列表五秒刷新，当前目标的线程与任务三秒刷新。切换目标使用 Query key 和 AbortSignal 隔离；隐藏目标停止轮询。Query key 里的完整目标 id 与页面选择分离；mutation 明确禁止自动重试。

## 7. 助手整合

### 7.1 命名与对象关系

| 用户名词 | 对应现有数据 | 允许的操作 |
| --- | --- | --- |
| 编码助手 | `RuntimeAgent` 启动配置 | 创建、查看配置、启动、删除配置 |
| 模型助手 | `Agent` 的模型与提示词配置 | 创建、独立 API 对话、删除配置 |
| 运行实例 | `RuntimeInstance` | 展示生命周期，按服务端权限停止/恢复 |
| 已接入会话 | 真实 `session` / `GraphNode` | 单聊、入房、查看图谱与详情 |

名称相同的模型助手 id=1 与编码助手 id=1 仍是不同对象，前端 key 必须加类型前缀。不得合并后端表、改写旧 id 或根据名字猜测关联。

### 7.2 助手页面

一个主入口，下分「编码助手」「模型助手」；默认显示编码助手，并在当前应用会话内保留所选分类。创建按钮直接进入当前分类的表单，表单中允许显式切换类型。复用现有 CreateAgentWizard 中两种表单，不再创建后又让用户猜去哪一页找。

编码助手列表中的每项显示启动配置，以及由完整 preset id 关联的受管实例和已接入会话。配置的标题不用「在线预设 / 离线预设」；可展示「运行中 2 个实例」「关联 1 个活跃会话」等有对象来源的统计。

启动成功先展示服务端返回的 starting 实例；只有取得真实 session_id 后才显示「打开会话」「进入聊天室」。同一预设允许展示多个实例；恢复创建新实例，历史记录保留。预设已删除但仍存在的实例放入「无关联配置的运行记录」，不能丢失控制或历史入口。

`can_stop`、`can_resume`、`limitation` 是按钮权限与原因的依据。失联不等于退出；未经身份校验的实例不能因界面整合获得停止/恢复能力。停止意图与确认退出分开显示，保持已有守卫。

外部接入、没有预设的会话仍在聊天侧栏和全局图谱中可见，不为其自动创建预设。终端区域复用现有 PtyPanel；切换分类或页面不自动启动、停止 CLI 进程，PTY 订阅按可见性管理并保留已有会话。

模型助手继续复用 ChatPanel 展示独立 API 对话，其创建成功后直接选中该助手。保留已有流式与取消语义，分类切换不重复提交模型调用。列表标明「独立对话」，本批不显示可加入聊天室的按钮。

## 8. 活动记录与已有能力保留

原全局消息流改名「活动记录」，继续支持现有过滤、读取、重试和详情。已有的已读副作用保留在活动页实际启用时，禁止因后台挂载此页而在应用启动时批量触发。

活动记录中的明确参与者可通过「打开对话」跳转到完整 session id 的单聊。任意两个外部会话间的边对话继续通过图谱 EdgeFlowView 查看，不能替换成只显示 web-console 消息的单聊。

设置、主题导入、终端配置、数据导入导出与清除入口保持可达。此批不改变数据备份、删除、写锁重试和外部动作的两相执行安全边界。

## 9. 错误、交互与兼容

- 加载中显示加载态，失败显示错误与重试，空结果才显示引导；不得把三者混为「没有房间」。
- 切换房间后旧房间的慢响应只能写回旧房间 query cache，不得覆盖新目标、滚动位置或草稿。
- 后台刷新失败保留上次成功内容并标示过期；连接恢复不自动重放 mutation。
- `@` 候选支持上下键、Enter、Esc；弹窗与抽屉支持焦点约束和关闭后焦点返回触发按钮。输入控件有可读标签，状态不能仅靠颜色辨认。
- 房间删除、移出成员、删除助手配置保留显式确认与错误反馈。发送、进程操作失败保留原资源 id，重试入口使用已有协议。
- 旧版数据库、配置、模型助手对话历史、编码预设和实例记录原样读取；本批无需 schema 迁移或协议迁移。

## 11. 交付与执行顺序

P1（聊天首页）→ P2（范围图谱与活动）→ P3（统一助手）→ P4（联调与打包）。每阶段独立 PR 到 dev，各阶段均保持已有功能可访问。内部代码拆分与测试可以逐提交交付，但不得让尚不存在的目标页面成为默认入口。

本规格、执行计划和规划 issue 的复选项只是计划；实施者按已取得的证据更新，不得提前标为完成。行为 PR 全绿后按仓库规则保留待审；dev→main、版本号、tag、发布分别遵循已有授权边界。本批不为 UI 调整自动发布 0.3.1 或其他版本。

P5 若启动，先单独设计成员类型、模型调用生命周期、上下文与费用、取消/重试、消息归属和迁移策略，再编写实现计划；不把模型助手 id 直接塞入 sessions.chat_room_id 体系。
